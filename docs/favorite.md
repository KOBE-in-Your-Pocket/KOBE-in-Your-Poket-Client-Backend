# お気に入り（PBI #227）

利用者が観光スポットに目印をつけておく仕組み。Client はマップのカード・観光一覧・観光詳細に
お気に入りマークを置き、プロフィール画面で自分のお気に入り一覧を見せる。

データの形と API の叩き台は Client 側（KOBE-in-Your-Pocket/KOBE-in-Your-Poket-Client#789）で決めたものに合わせている。

## API

いずれも認証必須・一般ロール可。本人は JWT の `sub` から決まり、他人のお気に入りは操作できない。
追加・解除はどちらも冪等なので、Client は「今の状態にする」つもりで何度呼んでもよい（連打や再送信で状態がずれない）。

### 追加 `PUT /api/v1/users/me/favorites/{spotId}`（#236）

| status | 条件 |
| --- | --- |
| 204 | 追加した（登録済みでも 204） |
| 400 | `spotId` が 128 文字を超える |
| 401 | 未ログイン |
| 404 | スポットが存在しない |

### 解除 `DELETE /api/v1/users/me/favorites/{spotId}`（#236）

| status | 条件 |
| --- | --- |
| 204 | 解除した（登録していないスポットでも 204） |
| 400 | `spotId` が 128 文字を超える |
| 401 | 未ログイン |

スポットの存在は確かめない。スポットが削除されたときは、お気に入りも一緒に消えるため（下記）。

### 一覧 `GET /api/v1/users/me/favorites`（#237）

| status | 条件 |
| --- | --- |
| 200 | 自分のお気に入り（0 件なら空配列） |
| 401 | 未ログイン |

```json
[
  { "spotId": "kobe-port-tower", "createdAt": "2026-11-02T10:00:00Z" },
  { "spotId": "kitano-ijinkan", "createdAt": "2026-11-01T10:00:00Z" }
]
```

- 並び順は登録日時（`createdAt`）の新しい順。同じ日時なら `spotId` の順
- スポットの名前や画像は含めない。Client は取得済みのスポット一覧と `spotId` で突き合わせて表示する
  （Client#789 の取り決め。多言語化を Client 側の 1 か所にまとめ、応答も軽くするため）
- 削除されたスポットは出ない（外部キーでお気に入りも消えるうえ、クエリでも `spot` と結合して絞っている）
- `GET /**` は公開のため、`SecurityConfig` でこのパスだけ先に認証必須にしている

## データ（`favorites` / V25）

| 列 | 内容 |
| --- | --- |
| `user_id` | お気に入りした利用者（Supabase Auth の user id） |
| `spot_id` | スポットの id |
| `created_at` | 登録日時。一覧を新しい順に並べるのに使う。登録済みのスポットを追加し直しても変わらない |

- 主キーは (`user_id`, `spot_id`)。同じスポットを 2 回登録しても 1 件
- `spot` へは外部キーを張り、スポットが削除されるとお気に入りも消える（`ON DELETE CASCADE`）
- `users` への外部キーは張らず、退会時にアプリ側で本人のお気に入りを全件削除する（`DeleteUserService` / #238）。Auth の削除が成功したあとに消すので、退会が成立しないままお気に入りだけ消えることは無い
