# ブロック（#215）

利用者が悪質なユーザーをブロックし、そのユーザーのレビューを自分の一覧に出さないようにする仕組み。
App Store Guideline 1.2（UGC）の「悪質なユーザーを利用者がブロックできる仕組み」に当たり、
通報（[`report.md`](./report.md)）と合わせてレビュー投稿を解禁する前提になる。

Client はレビューの三点リーダーに「ブロック」を置く。ブロックすると、ブロックした本人の画面から
そのユーザーのレビューがすべて消える（ミュートに近い挙動）。相手には通知しない。

## API

いずれも認証必須・一般ロール可。ブロックする側は JWT の `sub` から決まる。

### ブロック `PUT /api/v1/users/me/blocks/{userId}`

| status | 条件 |
| --- | --- |
| 204 | ブロックした（すでにブロック済みでも 204） |
| 400 | 自分自身 / `userId` が UUID でない |
| 401 | 未ログイン |
| 404 | ユーザーが存在しない |

`userId` はレビュー一覧の `author.id`。V17 以前の投稿など `author.id` が無いレビューの投稿者はブロックできない。

### 解除 `DELETE /api/v1/users/me/blocks/{userId}`

204（ブロックしていない相手でも 204）/ 400（`userId` が UUID でない）/ 401（未ログイン）。

### 一覧 `GET /api/v1/users/me/blocks`

ブロック中のユーザーを、ブロックした日時の新しい順に返す。設定画面の解除 UI に使う。

```json
[{ "id": "…", "name": "Troll", "iconUrl": null, "blockedAt": "2026-10-16T00:00:00Z" }]
```

## レビュー一覧への反映

`GET /api/v1/tourism/spots/{spotId}/reviews` に Bearer を付けると、本人がブロック中の投稿者の
レビューを除いて返す。Bearer が無ければ従来どおり全件を返す。

Client はブロック直後に、再取得を待たずにその投稿者のレビューを画面から消す。以後の取得では
サーバー側で除外される。

## データ（`user_blocks` / V23）

| 列 | 内容 |
| --- | --- |
| `blocker_user_id` | ブロックした利用者 |
| `blocked_user_id` | ブロックされた利用者 |
| `created_at` | ブロックした日時 |

主キーは (`blocker_user_id`, `blocked_user_id`)。自分自身のブロックは CHECK 制約でも弾く。
`users` への外部キーは張らず、退会時にアプリ側で本人がした・本人がされたブロックを両方削除する。

## 既知の制限

- 運営向けの「ブロックされているユーザー」一覧はまだ無い。記録はサーバーに残っているため、必要になれば
  `user_blocks` を集計して追加できる
- ブロックはレビューの表示にだけ効く。現状、利用者同士がやり取りする機能は無い
