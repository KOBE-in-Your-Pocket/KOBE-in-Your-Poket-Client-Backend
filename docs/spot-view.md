# 観光スポットの閲覧数（PBI #228）

外国人観光客が「みんなが注目している場所」を知れるように、観光スポットの閲覧数を数える。
Client は観光スポットのカードから詳細画面に遷移したときに 1 回記録する（KOBE-in-Your-Pocket/KOBE-in-Your-Poket-Client#777）。

## API

### 閲覧を数える `POST /api/v1/tourism/spots/{spotId}/views`（#240）

未ログインでも呼べる（公開）。誰が閲覧したかは記録しない。リクエストボディは無い。

| status | 条件 |
| --- | --- |
| 204 | 閲覧を 1 回数えた |
| 400 | `spotId` が 128 文字を超える |
| 401 | 無効なトークン（期限切れなど）を付けた |
| 404 | スポットが存在しない |
| 429 | 同じ IP から 1 分に 60 回を超えた（`Retry-After` 付き） |

- **トークンは付けずに呼ぶ**。公開 API でも、付けたトークンは検証されるため、期限切れのトークンを付けると 401 になる
- 同じ IP から同じスポットへの閲覧は 10 分に 1 回だけ数える（下記「重複・連打のまとめ方」）
- 同時に呼ばれても数はずれない（記録は行の追加だけ。下記）
- 閲覧数はおまけの情報なので、Client は結果を待たず、失敗しても画面の操作を止めない

### 重複・連打のまとめ方（#260 / 決めた経緯は #242）

| 場合 | 扱い |
| --- | --- |
| 同じ IP × 同じスポットを 10 分以内にもう一度呼んだ（連打を含む） | **1 回だけ数える**。2 回目以降も 204 を返し、数えないだけ |
| 同じ IP から 1 分に 60 回を超えた | **429**（`Retry-After` 付き）。超えた時点から 1 分間止まる |
| 別のスポット、別の IP、または 10 分経ったあと | 数える |
| 存在しないスポット（404） | まとめる対象として数えない（あとでスポットができれば 1 回目として数える）。429 の回数には入る |

- 利用者 IP は `request.remoteAddr`。本番は Caddy の `X-Forwarded-For` を Tomcat が解釈した実 IP（ログインのレート制限 #244 と同じ）
- カウンタはインメモリ（EC2 1 台構成のため）。再起動で消えるのは許容する。IP は DB に保存しない
- ホテルの Wi-Fi やキャリアの CGNAT で IP を共有している人は、10 分以内に同じスポットを開くと 1 回と数えられる（少なめに出る）。許容する
- 同じ IP から同時に呼ばれても 2 回数えない（判定と加算を 1 つの操作で行う）
- 実装: 重複まとめは `RecordSpotViewService` → `SpotViewDeduplicator`（`InMemorySpotViewDeduplicator`）、429 は `SpotViewIpRateLimitFilter`

回数・時間は環境変数で変えられる（`application.yml` の `spot-view.rate-limit`）。

| 環境変数 | 既定 | 意味 |
| --- | --- | --- |
| `SPOT_VIEW_DEDUPE_WINDOW` | `10m` | 同じ IP × 同じスポットを 1 回にまとめる時間 |
| `SPOT_VIEW_IP_MAX_REQUESTS` | `60` | 同じ IP からの呼び出しの上限回数 |
| `SPOT_VIEW_IP_WINDOW` | `1m` | 上の回数を数える時間（超えたらこの時間 429） |

### スポット詳細で閲覧数を返す `GET /api/v1/tourism/spots/{id}`（#256）

既存のスポット詳細のレスポンスに `viewCount` を足した。未ログインでも取れる（公開）。Client は詳細画面に「閲覧数 ○回」を出す（KOBE-in-Your-Pocket/KOBE-in-Your-Poket-Client#836）。

```json
{ "id": "kobe-port-tower", "name": "神戸ポートタワー", "...": "...", "viewCount": 12 }
```

- 全期間の合計。閲覧がまだ無いスポットは `0`
- 一覧（`GET /api/v1/tourism/spots`）・登録・更新のレスポンスには載せない（キーごと出ない）。一覧で使う場面が無く、スポットごとに COUNT が要るため
- 詳細画面を開く前に閲覧を記録するので、記録が先に届けば自分の 1 回も含んだ数になる。記録は結果を待たないため、含まれないこともある

### スポット別の閲覧数 `GET /api/v1/stats/spot-views`（#241）

運営向け（管理画面 KOBE-in-Your-Pocket-ADMIN で使う）。`OPERATOR` 以上のみ（ロール階層で `ADMIN` も可）。
ダッシュボードの `GET /api/v1/stats` にそろえて `/api/v1/stats` の下に置く。

| status | 条件 |
| --- | --- |
| 200 | 一覧を返した（閲覧が 1 件も無ければ `[]`） |
| 401 | 未認証 |
| 403 | `OPERATOR` 未満（一般ユーザー） |

```json
[
  { "spotId": "arima-onsen", "name": "有馬温泉", "viewCount": 12 },
  { "spotId": "kobe-port-tower", "name": "神戸ポートタワー", "viewCount": 3 }
]
```

- 閲覧数の多い順。同数は `spotId` 順（毎回同じ並びになる）
- 閲覧が 1 件も無いスポットは含めない
- 件数は全期間の合計。上限・ページングは無し（スポットは数十件の想定）
- `name` は `?lang=` → `Accept-Language` → 既定（en）の順で決めた言語で返す。その言語の名前が無ければ en、それも無ければ `spotId`

## データ（V26 / #239）

閲覧 1 回 = `spot_views` の 1 行（`id` / `spot_id` / `viewed_at`）。

- 合計の 1 行を更新するのではなく行を足すだけなので、同時に記録されても数がずれない
- 閲覧数は `COUNT` で出す（`SpotViewCountQuery`）。今は合計（全期間）だけ。`viewed_at` があるので日別・期間別もあとから出せる
- スポットが削除されると、閲覧の記録も一緒に消える（`ON DELETE CASCADE`）
